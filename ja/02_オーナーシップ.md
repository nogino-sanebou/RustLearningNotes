# ownership
## ownershipが必要な理由
Rustの変数には借用という独特なシステムがあります。

ややこしいですが、私的には理解できれば納得できますし、
逆に分かり易いシステムまであると思いました。

結構現実世界に置き換え易いシステムなんですよね。

### ownershipがないとどうなるか

```rust
fn main() {
    let s1 = String::from("Hello, world");
    let s2 = s1;

    println!("{}", s1);
}
```
としたときコンパイルエラーになります。
これはownershipが`s1`から`s2`にmoveされるからです。

なぜこんなことになっているかというと、
二重解放を防ぐためです。

二重解放とは、`s1`が解放されているのに`s2`も解放しようとして予期せぬ処理が発生するからです。

例えば`s1`を解放した後に別の変数のデータ解放されて空いた元`s1`のアドレスに置かれたとします。

ここで`s2`の解放処理が動くと別な変数のデータを解放してしまう事になります。

これは実装者が望む動きではありません。

つまり
```rust
fn main() {
    let s1 = String::from("Hello, world");
    let s2 = s1;

    drop(s1);

    let s3 = String::from("Hello, world");

    drop(s2);
}
```
とすると`drop(s2)`の処理で`s3`の領域を解放する可能性があるということですね。

これの面倒なところは毎回必ずしも`s3`が旧`s1`の位置に置かれるわけではないので
実行時に特にエラーなく動作してしまうこともあるのが更に問題になります。

これを回避するために、`s2`に`s1`のデータを移動し、`s1`を使えなくさせています。

このような動きをムーブセマンティクスと呼びます。

ただ全ての変数がそうであるかというと、そういうわけではありません。

例えば整数型などのスタックにのみデータを置く変数はデータの移動が発生しません。
ではどうなるかというとコピーされます。

小さいデータなのでサイズが倍になったところで余りパフォーマンスに影響がでないですからね。

逆にヒープのデータは巨大になりますのでコピーはパフォーマンスに影響がでてくるということです。

このような動きをコピーセマンティクスを呼びます。

ただ、Rustでは`Copyトレイト`を実装した型がコピーセマンティクスになるため、
使い方によっては巨大なデータになる可能性があることには注意が必要です。

また、先ほど挙げたコード例はイメージ上の説明です。
実際のRustでは`s1`はMove済みのため、
`drop(s1)`でコンパイルエラーになるため実際には書けません。

### s1を使えなくさせるとはどういうことなのか
先ほどムーブセマンティクスにより`s2 = s1`で`s1`が使えなくさせている、と言いましたが、
何故このような表現をしたかというと、`s2 = s1`で直ちに`s1`がメモリ上から消えるわけではないからです。

メモリ上はそのままでプログラムはアクセスできないだけになっています。
(ただし、コンパイラ最適化によって実際の配置は変わる可能性があります)

では何処で消えるのかというと、move先の変数がスコープを抜ける際に解放されます。

move元を即座に消す必要がないため、
Rustは変数を使えない状態にすることで所有権を管理しているのですね。

### シャドーイングはどうなのか
Rustでは
```rust
fn main() {
    let x = 10;
    {
        let x = 30;
        println!("x={}", x);
    }
    println!("x={}", x);
}
```
のようなコーディングができます。
この際の結果は
```
x=30
x=10
```
となります。
これは`x`がシャドーイングされているからなのですが、
メモリ上はどうなっているかというと、
```
┌───────┐
│x = 30 │
├───────┤
│x = 10 │
└───────┘
```
のようなイメージなっており、内側のスコープを抜けるまで外側の`x`は隠されているわけですね。

### RAII
Rustの変数はスコープ単位でリソースの寿命を管理します。
この思想をRAIIというようです。
使う機会があるかわかりませんが、取り合えず知ったことなので記録しておきます。

## borrow
Stringはムーブセマンティクスなので一度moveするとmove元の変数は使えなくなります。
これはプログラムが堅牢になって良いのですが、困ってしまう事もあります。

例えば以下のようなコードがあったとします。
```rust
fn main() {
    let msg = String::from("hello");
    
    print(msg);
    
    println!("{}", msg);
}

fn print(msg: String) {
    println!("{}", msg);
}
```

一見動きそうに見えますが、実はこれはコンパイルエラーになります。

何故かというと`print`関数に引数として`msg`を渡した際に所有権が`print`の
引数の`msg`にmoveされてしまうからです。

`print`を実行した時点で`main`の`msg`は所有権を失っているので`println!("{}", msg);`
が実行できずコンパイルエラーになってしまいます。

これは流石に困ります。
そこで登場するのがborrowです。

borrowは借りるという意味で、これを使う事で所有権を移動せずに変数の値にアクセスできます。

borrowには`&`を使用します。

先ほどのRustの例をborrowを使うと
```rust
fn main() {
    let msg = String::from("hello");
    
    print(&msg);
    
    println!("{}", msg);
}

fn print(msg: &String) {
    println!("{}", msg);
}
```
このようにコーディングすることで`print`関数は`msg`の所有権を貰う訳ではなく、
借りる形で参照できるようになります。

勿論関数以外でもborrowはできます。
```rust
fn main() {
    let x = String::from("hello");
    let y = &x;
    
    println!("x = {}", x);
    println!("y = {}", y);
}
```
はコンパイルでき、実行結果は
```
x = hello
y = hello
```
となります。

ただ以下のようなコードはコンパイルできません。
```rust
fn main() {
    let x = String::from("hello");
    drop(x);

    let y = &x;

    println!("x = {}", x);
    println!("y = {}", y);
}
```
わかると思いますが、既に`x`が`drop`され、所有権も無い状態ですので
`y`も借りられるものがないのでコンパイルエラーになります。

### borrowのborrowはできるのか
できます。
Rustではborrowした変数を更にborrowすることができます。

以下のようなコードです。
```rust
fn main() {
    let x = String::from("hello");
    let y = &x;
    let z = &y;
}
```

この時、メモリは以下のようなイメージになっています。
```
┌───────────────────────────┬─────────────────────────────────┬─────────────────────────────────┐
│ x=ヒープにあるhelloの情報 │ y=xの置かれているメモリアドレス │ z=yの置かれているメモリアドレス │
└───────────────────────────┴─────────────────────────────────┴─────────────────────────────────┘
```
`z`は`y`を見ていて、`y`は`x`を見ていて、`x`はヒープのデータと繋がっている。

このようにborrowが連鎖している為、`z`も`hello`を見る事ができるわけですね。

### borrowを表現する型
数値は例えば`i32`などありますが、borrowした変数は型が変わります。

それは型名に`&`が付きます。

例えば
```rust
fn main() {
    let x = 10;
    let y = &x;
}
```
の場合
```
x: i32
y: &i32
```
となります。

更に
```rust
fn main() {
    let x = 10;
    let y = &x;
    let z = &y;
}
```
の場合
```
x: i32
y: &i32
z: &&i32
```
のように&が増えます。
特に発生するパターンはありませんが、
`&&&&&&&&&&&&&&&&&i32`のような型もあり得ます。

### デリファレンス(dereference)
デリファレンスとは参照先の値を読む事です。

例えば
```rust
fn main() {
    let x = 10;
    let y = &x;
 
    print(y);
}

fn print(x: i32) {
    println!("x={}", x);
}
```
はコンパイルエラーになります。

これは`print`関数が`i32`を求めているの対し、`y`は`&i32型`ですからね。

こんな時にデリファレンスで実体を渡せます。
```rust
fn main() {
    let x = 10;
    let y = &x;
 
    print(*y);
}

fn print(x: i32) {
    println!("x={}", x);
}
```
と`*`を付ける事でデリファレンスでき、コンパイルが通ります。

更に`let z = &y;`などのborrowのborrowがあった場合も、
```rust
fn main() {
    let x = 10;
    let y = &x;
    let z = &y;
 
    print(**z);
}

fn print(x: i32) {
    println!("x={}", x);
}
```
と`*`を繋げることで参照を辿っていくことができます。

他にも
```rust
fn main() {
    let x = 10;
    let y = &x;
    let z = &y;

    println!("x={}", x + y + z);
}
```
というコードがあった場合、
`z`が見ている先が`10`ではなく`&y`なので`x + y + z`ができません。

こういった場合も
```rust
fn main() {
    let x = 10;
    let y = &x;
    let z = &y;

    println!("x={}", x + y + *z);
}
```
とデリファレンスを使うことで計算することが可能となります。

基本の概念とはして上記の通りですが、Rustには自動デリファレンスという機能があるので、
必ずしも`*`が必要とは限りません。

ですので個人的にはIDEがエラーを吐いたら`*`を付けるくらいのノリでも良いかと思います。

勿論、事前にわかることに越したことはありませんが。

### 変更可能なborrow
Rustでは`&mut`を使うことでborrowした変数から値を変更することが可能です。

以下のような感じです。
```rust
fn main() {
    let mut x = 10;
    let y = &mut x;
}
```

ここから`y`に対して値を変更したい場合、デリファレンスを使用します。

以下のようになります。
```rust
fn main() {
    let mut x = 10;
    let y = &mut x;

    *y = 100;

    println!("y={}", y);
    println!("x={}", x);
}
```
このコードの実行結果は
```
y=100
x=100
```
になります。

ただここで注意点があります。

`x`は`y`の利用されなくなるまでアクセスはできません。
```rust
fn main() {
    let mut x = 10;
    let y = &mut x;

    x = 200;
    *y = 100;

    println!("y={}", y);
    println!("x={}", x);
}
```
のような処理や
```rust
fn main() {
    let mut x = 10;
    let y = &mut x;

    *y = 100;

    println!("x={}", x);
    println!("y={}", y);
}
```
のような`y`を利用している最中に`x`を利用することはできません。

これはborrowのborrowも同様で
```rust
fn main() {
    let mut x = 10;
    let mut y = &mut x;
    let z = &mut y;

    **z = 200;
    *y = 100;

    println!("x={}", x);
}
```
は通っても
```rust
fn main() {
    let mut x = 10;
    let mut y = &mut x;
    let z = &mut y;
    
    *y = 100;
    **z = 200;

    println!("x={}", x);
}
```
はコンパイルエラーになります。

また、変更可能なborrowを宣言できるのは1つのみです。
```rust
fn main() {
    let mut x = 10;
    let y = &mut x;
    
    *y = 100;
}
```
は通りますが、
```rust
fn main() {
    let mut x = 10;
    let y = &mut x;
    let z = &mut x;

    *z = 100;
    *y = 200;
}
```
は通りません。
`z`の利用期間中に`x`や`y`が使われていないから大丈夫ということはありません。

```rust
fn main() {
    let mut x = 10;
    let mut y = &mut x;
    let z = &mut y;

    **z = 200;
    *y = 100;

    println!("x={}", x);
}
```
はあくまでもborrowのborrowなのであって
同じ変数を複数の変数が変更可能なborrowをしているわけではないからです。

詳しく言うと、型としては`&mut (&mut i32)`で、
`x`への可変参照を更に可変参照しているという事です。
