# ライフタイム

ライフタイムは名前の通りで、変数の参照先が生きている期間の事を言います。

```rust
fn main() {
    let x = 10;

    {
        let y = 20;
    }
}
```
の場合、`x` のライフタイムは `main関数` を抜けるまでで、
`y` は6行目の `}` を抜けるまでです。

この変数の寿命を明示することができます。
それが `'a` です。

```rust
fn func_a<'a>(x: &'a i32) {
    
}
```
のようにすることで変数 `x` は `'a` の間だけライフタイムがあることを明示できます。

例のコードはこのライフタイムを省略することが可能なので
```rust
fn func_a(x: &i32) {
    
}
```
という書き方ができます。

ではどういった場面でライフタイムを明示する必要があるのでしょうか？

それはライフタイムがどうなるのか曖昧になるパターンです。

```rust
fn func_a(x: &i32, y: &i32) -> &i32{
    if *x == 10 {
        x
    } else {
        y
    }
}
```
このようなコードがあった場合、コンパイラがエラーを出します。

この関数では `x` が `10` であった場合は `x` をそうで無かった場合は`y`という
渡ってきた変数を返すような処理になっています。

この際、関数からは `x` と `y` のライフライムが分からないので戻り値である`&i32`のライフタイムも
不明になります。

この場合、ライフタイムを明示する必要があります。

それが以下です。
```rust
fn func_a<'a>(x: &'a i32, y: &'a i32) -> &'a i32{
    if *x == 10 {
        x
    } else {
        y
    }
}
```

`'a` を使ってライフタイムを使用することで `x` と `y` と戻り値のライフタイムが短い方に合わせられます。

この明示により
```rust
fn main() {
    let x = 10;
    let z;

    {
        let y = 20;

        z = func_a(&x, &y);
    }

    println!("{}", z);
}

fn func_a<'a>(x: &'a i32, y: &'a i32) -> &'a i32{
    if *x == 10 {
        x
    } else {
        y
    }
}
```
というようなライフタイムの違う変数を `func_a関数` はborrowできません。

`func_a関数` の呼び出し元の関数は、 `x` より `y` の方がライフタイムが短いですからね。

逆に
```rust
fn main() {
    let x = 10;
    let z;

    {
        let y = 20;

        z = func_a(&x, &y);
    }

    println!("{}", z);
}

fn func_a<'a, 'b>(x: &'a i32, y: &'b i32) -> &'a i32{
    x
}
```
とあれば戻り値は `'a` がライフタイムになるので
つまりは呼び出し元の変数 `x` のライフタイムと同じなるわけです。

ですので、 `println!("{}", z);` まで戻り値の参照が消える事がないこと明示しています。

それによりこのパターンではコンパイルエラーになりません。

逆に
```rust
fn main() {
    let x = 10;
    let z;

    {
        let y = 20;

        z = func_a(&x, &y);
    }

    println!("{}", z);
}

fn func_a<'a, 'b>(x: &'a i32, y: &'b i32) -> &'b i32{
    y
}
```
とあると `'b` のライフタイムは呼び出し元の変数 `y` のライフタイムと同じになるので
 `println!("{}", z);` まで `z` は生存できない事が分かります。

つまりこのパターンはコンパイルエラーになるわけですね。

## struct のライフタイム
例えば
```rust
struct User {
    name: &str,
}
```
はコンパイルエラーになります。

何故かというと、 `name` の参照がどれだけ生きるのか分からないからです。

Rust のコンパイラーはこういった参照の生存期間が曖昧な事を嫌います。

```rust
struct User<'a> {
    name: &'a str,
}
```
とライフタイムを付けることで

```rust
fn main() {
    let user;

    {
        let s = String::from("Alice");
        
        user = User {
            name: s.as_str(),
        };
    }
    
    println!("{}", user.name);
}
```
だと `s` のライフタイムは `{` のブロックの間だけなので、
`User` の `name` もそのライフタイムであることをコンパイラーが認識できるので
 `println("{}", user.name);` で既にライフタイムが切れているのでコンパイルエラーにできます。

ですので、逆に
```rust
fn main() {
    let user;
    let s = String::from("Alice");
        
    user = User {
        name: s.as_str(),
    };
    
    println!("{}", user.name);
}
```
とするとコンパイルエラーは解消されます。

一方でライフタイムを付けなくとも良い場合もあります。

それは変数の型が参照型でない場合です。

つまり
```rust
struct User {
    name: String,
}
```
は許可されます。

`User<'a>` は、`'a` の間だけ有効な `&str` を保持する構造体です。

そのため、`User` の値は `name` の参照先より長く生きることができません。

ただ `String` 型の場合、 `User` のライフタイムが終了すると `name` も同時に終了します。

つまり `name` の生存状態をコンパイラーは把握することが可能ですので、ライフタイムを付ける必要がないのです。

ここで気になるのは関数の場合はライフタイムを省略可能ですが、struct の場合はどうなるかです。

結論、struct の場合はライフタイムを省略できません。

関数ではライフタイム省略規則により、一定のパターンなら省略できます。

一方で struct のフィールドに参照を持たせる場合は、
どのライフタイムの参照を保持する型なのかを型定義上に書く必要があるため、省略できません。
